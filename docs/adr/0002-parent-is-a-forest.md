# 0002. 母子關係是任意深度的森林

## 背景

`MapIssue.parent` 是一個指向另一張票的指標。GitHub 原生 sub-issue 本來就允許巢狀，抓取時也對
所有 parent 展開，所以三層以上的鏈會完整進快照。

清單原本把它當成兩層結構處理：有 parent 的是子票、沒有的是主票，再補一條例外「有子票入選但
自己沒入選的主票要撿回來當標頭」。三層鏈的中間那張同時符合兩邊，於是渲染成兩列，兩列帶同一個
`data-number`——選取時一起亮、就地展開只開得到其中一列、張數也多算一張。

收合也建立在同一個假設上：`paintFolded` 只比對節點的直屬 `data-parent`。第三層的
`data-parent` 指向第二層，所以收起最上層時它會單獨留在畫面上。

## 決定

清單真的把票折成森林，再深度優先展平。每張票只出現一次，`Row` 帶 `depth`，縮排的級距留在
CSS（`--depth`）。

收合看的是**整條祖先鏈**：任何一個祖先被收起來，底下所有層級都跟著藏。

資料成環時止血——遞迴遇到走過的票就停，而且環裡的票仍以頂層出現，不會整批消失。

## 代價

- `Row` 多一個欄位，`rowOrder` 從兩層迴圈變成遞迴。遞迴深度等於 parent 鏈長度，實務上是個位數。
- 收合每畫一次就要走一次祖先鏈。鏈很短，而且只在收合狀態改變時走。
- 展平與排序仍住在 view 而不是 model。`groupsOf` 已經在做一次 parent 分群，森林嚴格說是模型的
  工作；沒搬是因為排序用的是 view 的比較函式，搬過去要一併決定模型該不該管排序。
