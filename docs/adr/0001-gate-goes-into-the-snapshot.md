# 0001. 狀態機套用的閘門要進快照

## 背景

一張票沒掛角色標籤時算不算「還沒評估完」，取決於這個 repo 到底有沒有在用那組標籤。抓完之後
從看到的標籤聯集嗅出這件事（`triaged`），交給狀態機當閘門——都沒看到就不套，否則每張票都會
變成待 triage。

這個判定原本只是 `takeSnapshot()` 裡的一個區域變數。快照送出去的只有字彙本身
（`labels.ready` / `labels.unready`），而字彙一律有預設值、永遠非空。

頁尾要告訴讀圖的人「這一次的閘門是什麼」，於是它只能看 `labels.ready.length` 重猜。那個值
永遠為真，所以那句話永遠印成「沒掛角色標籤等於未定案」——而閘門沒套用時，票其實是照前置判成
可動的。頁面一邊說可以動，一邊說它未定案；`foot.noVocab` 那一句在預設設定下永遠印不出來。

## 決定

把判定本身寫進快照：`labels.gated: boolean`。頁尾讀它。

同一件事只有一個來源。下游要知道「這一次有沒有套閘門」時一律讀這個欄位，不從別的訊號推。

## 代價

- `Snapshot` 的形狀變了，建置側與畫面側都要跟。這是刻意的：漏掉哪一邊編譯就不過。
- `gated` 仍然是從**抓到的那批票**的標籤聯集嗅出來的，不是查 repo 定義了哪些標籤。標籤剛導入、
  或當下 open 票剛好都沒掛，整個 repo 的狀態語意還是會靜默切換模式。要根治得多打一趟
  `repository.labels`，或讓它變成明確設定。這份記錄不處理那件事，只處理「同一件事有兩個來源」。
